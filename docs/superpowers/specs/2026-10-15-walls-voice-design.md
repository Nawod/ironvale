# Wall alignment and multiplayer voice

The user wants enclosure sides to face along their wall runs, plus optional live voice in both the online lobby and match. Free-for-all uses an open channel. Team matches offer Open and Team channels; Team includes only teammates currently using that channel. Players can switch, mute/unmute their microphone, mute incoming audio and leave voice. Existing cities, teams, resources, zombie mode, worker task memory and building appearance stay intact.

Wall yaw comes from adjacent known wall/palisade/gate footprints in the current snapshot. Horizontal runs use the existing orientation; perpendicular runs rotate 90 degrees. Corners/ties and isolated pieces have stable defaults. Compute adjacency once per snapshot, including known fog ghosts, without inspecting hidden simulation state or rotating whole buildings.

Voice uses browser WebRTC audio and the existing authenticated room WebSocket for signaling. Maximum eight participants keeps an audio mesh bounded to seven connections per player. The server forwards only between connected, opted-in human seats in the same room and selected channel. Team checks use authoritative assignments. Both endpoints carry current membership epochs so old offers/candidates cannot reconnect a prior channel. Team/mode changes clear voice memberships; room start preserves them. Disconnect, replacement, leave and teardown remove peers and stop microphone capture. Voice is never saved, recorded or mixed into simulation snapshots.

Joining requires a user action and microphone permission. Join starts muted; capture tracks are disabled before creating connections. Switching channels disables the track and closes all old peer connections/audio elements before requesting new membership, and resets the microphone to muted. New connections wait for server membership acknowledgement. Browser permission errors, blocked autoplay and ICE failure get readable states. Incoming-audio mute is independent of microphone mute. No camera access, paid service, new account or package dependency.

WebRTC requires HTTPS away from localhost; the interface explains this when unavailable. The server provides optional configured ICE servers for STUN/TURN, with a public STUN default and no purchased relay. Documentation covers HTTPS deployment and TURN for restrictive networks. Automated verification uses fake microphones and real browser peer connections/audio statistics; this does not substitute for a physical-device or public-internet call.
